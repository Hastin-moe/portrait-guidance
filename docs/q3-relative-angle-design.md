## 0. 一句话结论

Q3 的「相对夹角」= 在 S6 场地图上，以**模特站位（或人物元素）为顶点**，实时算出四种静态几何关系的**水平夹角（及必要距离）**；灯→模特可额外显示**高度角**（依赖 Q7 灯高/俯仰），其余三种默认**只做水平**。不画走位路线；坐标显示与计算统一用**棚左下角原点**。

---

## 1. 定义与坐标系

### 1.1 名词

| 词 | 含义 |
|---|---|
| **站位点** | 某位模特在某个镜头/布光方案下的静态落点；记平面坐标 + 朝向；可挂动作、镜头。不画路径。 |
| **被摄者 / 顶点** | 夹角计算的公共顶点。优先取「当前上下文的站位点」；若无站位，回退到本 setup 内该模特的 `person` 元素。 |
| **相对夹角** | 以被摄者平面位置为顶点，两条方向向量之间的有符号水平角；**不是**元素自身 `rot` 的绝对值。 |
| **光位名** | 由水平夹角绝对值映射的口语标签（正面光 / 伦勃朗 / 侧光…），仅展示，不入库为权威值。 |

### 1.2 平面坐标系（Q3 已定）

```
Y↑（棚深方向，向上为正）
│
│    · 左下角 = (0, 0)
│
└──────────────→ X（棚宽方向，向右为正）
棚左下角
```

- 单位：**米（m）**。
- 棚矩形：`x ∈ [0, venue.w]`，`y ∈ [0, venue.d]`（`venue.w` / `venue.d` 来自 S2）。
- **显示与相对计算**一律用此原点。
- **存储**：可继续用现有「画布 y 向下」内部坐标；换算约定：

  ```
  y_display = venue.d − y_storage
  x_display = x_storage
  ```

  （与确认稿「Y 显示 = 场地深度 − Y 存储」一致；0.3.0 项目不迁移文件。）

### 1.3 朝向角约定（建议，待审）

现状（审阅更正）：存储系里 `rot` 是 0° 朝 +X、**朝存储 +y（画布向下）增大**，在屏幕上看是**顺时针**。原稿写成「逆时针」是错的。

换原点后 Y 翻转，角度也必须跟着换算，否则显示出来的朝向会和画面相反：

```
rot_display = (360 − rot_storage) mod 360      // 显示系：0° 朝右，逆时针增大
rot_storage = (360 − rot_display) mod 360      // 输入时换回
```

所有相对夹角都在**显示系**里计算（先把 x、y、rot 换算到显示系，再套 §2 的公式），这样 α 的正负才对应「左」和「右」。UI 文案：「0° 朝右，逆时针为正」。

人物/站位的「正前方」= 其 `rot`（或站位 `heading`）所指方向。

### 1.4 高度（仅关系 1 用）

| 量 | 来源 | 默认 |
|---|---|---|
| 灯高 `heightM` | 灯元素（Q7） | 未填则不显示高度角（不做估算） |
| 灯俯仰 `pitchDeg` | 灯元素；**向下为负**（Q7） | 0 |
| 脸高 | 人物身高 − 0.12 m（S3 填了身高时） | 未填身高按 **1.55 m**（与三维预览眼高一致） |
| 相机高 | 本期可不进四种关系 | — |

平面距离：`d_xy = hypot(Δx, Δy)`。  
斜距（灯→脸）：`d_slant = hypot(d_xy, heightM − faceHeight)`。

## 2. 四种关系的几何定义

公共前提：

- 顶点 **S** = 被摄者平面点 `(Sx, Sy)`。
- 模特正前单位向量：`F = (cos θs, sin θs)`，`θs` = 站位/人物朝向。
- 有符号水平角：向量 `V` 相对 `F` 的夹角  
  `α = atan2(Fx·Vy − Fy·Vx, Fx·Vx + Fy·Vy)` → 映射到 **(−180°, 180°]**。  
  **α > 0 = 被摄者左侧**（从模特自身朝向看）；**α < 0 = 右侧**。（若 Hastin 习惯相反，见 §6。）
- 展示用绝对值 `|α|` + 「左/右」；光位名用 `|α|`。

### 2.1 灯 → 模特

| 项 | 定义 |
|---|---|
| 向量 | `V_L = (Lx − Sx, Ly − Sy)`（从模特指向灯的平面方向） |
| **水平夹角** | `α_light`：`V_L` 相对模特正前 `F` |
| **距离** | 平面距 `d_xy`；有灯高时另给斜距 `d_slant` |
| **高度角** | **含俯仰展示（建议本期做）**：`β = atan2(heightM − faceHeight, d_xy)`（灯相对脸的仰角；灯更高则为正）。灯自身 `pitchDeg` 用于「灯是否对准脸」的辅助提示，**不替代** β，也不进光位名。 |
| 光位名（水平） | 0° 正面光；≈45° 伦勃朗；90° 侧光；135° 侧逆；180° 逆光（区间可微调，见 §6） |
| 配对规则 | 默认：当前布光方案内、到顶点距离最近且有效的灯；多灯时**每盏各算一行**，主显示可选「主光」或最近灯 |
| 不含 | 不把「灯相对机位轴线」算进本四种关系（那是 T24 附加标注，见 §5） |

### 2.2 相机 → 模特

| 项 | 定义 |
|---|---|
| 向量 | `V_C = (Cx − Sx, Cy − Sy)`（从模特指向机位） |
| **水平夹角** | `α_cam`：`V_C` 相对模特正前 `F` |
| **距离** | 仅平面距 `d_xy` |
| **俯仰** | **本期不含**（相机高未进四种关系）。可选文案档：正面 / ¾ / 侧面 / 侧背 / 背面（按 `|α_cam|`） |
| 配对 | 优先镜头绑定的 `cameraId`；否则 setup 内最近机位 |
| 附加（非夹角） | 焦段估算画面高度可继续做，属机位 UX，不算第五种「相对夹角」 |

### 2.3 模特 → 背景板

| 项 | 定义 |
|---|---|
| 对象 | `kind === "backdrop"` 元素（背景纸/板的平面条） |
| **距离** | 模特点到背景板**线段/矩形近边**的最短距离（建议）；MVP 可先用中心点距，审后升级 |
| **水平夹角** | `α_bg`：从模特指向背景板最近点（或中心）的方向，相对模特正前 `F`。用于回答「背景在模特的左前/正后…」 |
| **俯仰** | **不含** |
| 配对 | 最近一块 backdrop；多块时列表，主显示最近 |

说明：确认稿写「到背景的距离」；夹角一并给出，满足「相对背景」的完整表述。若审稿认为背景只需距离、不要角，可降级为「距离必显、夹角可选」。

### 2.4 模特 → 自然光窗户面

| 项 | 定义 |
|---|---|
| 对象 | `layout.base` 中 `kind === "window"`（场地固定窗）；**不是** S2 文本字段 `venue.windowDir` |
| **窗户面法向** | 窗元素平面条的朝向：由 `rot` 推出**指向棚内的法向** `N`（窗厚方向；若 `rot` 表示窗长轴，则法向 = `rot ± 90°`，取指向棚心的一侧） |
| **水平夹角** | 两种可展示量，建议**主显 A、辅显 B**： |
| | **A. 窗光方位角** `α_win`：从模特指向窗面最近点（或窗中心）的方向，相对模特正前 `F`（「窗在模特左后方」） |
| | **B. 入射角（可选）**：窗内法向 `N` 与 `S→窗` 反向（光大致入射方向）的夹角，用于「是否贴窗 / 侧窗光」 |
| **距离** | 模特到窗线段的最短距 |
| **俯仰** | **不含**（窗高未建模时不做；有窗台高度后再议） |
| 配对 | 最近的 window；无窗则整行隐藏并提示「场地未标窗」 |

与 `venue.windowDir`：S2 保留口语备注；几何关系**只认场地图上的 window 元素**。

## 3. UI 放在哪（S6：站位 / 灯 / 机位）

原则：**计算只做一份**；入口按选中对象切换「以谁为焦点」的展示。编辑仍走二级层（T17/T23）；夹角是只读实时标注 +「关系」表。

### 3.1 画布实时层（T24 主表面）

选中或拖动时，以被摄者为圆心画弧 + 数字（量角器），旁注光位名 / 左·右。

| 选中对象 | 画布上主显的关系 |
|---|---|
| **站位点** 或 **人物** | ① 面前各灯的水平角（小扇形）；② 到机位；③ 到背景距离（+夹角）；④ 到最近窗 |
| **灯** | 灯→当前被摄者：距离、水平角、高度角；左/右与光位名 |
| **机位** | 机位→被摄者：距离、水平角（正面/¾…） |
| **背景 / 窗** | 可选：到当前被摄者的距离（反向查看）；非必须 |

「当前被摄者」解析顺序：

1. 本 setup 显式选中的站位 / person；  
2. 否则 setup.`ex.subjectId`（与 EX 共用）；  
3. 否则最近 person / 站位。

### 3.2 二级编辑 ·「关系」页

| 对象 | 关系页内容 |
|---|---|
| **灯** | 表：到被摄者平面距、斜距、α_light、左右、光位名、高度角 β；被摄者下拉 |
| **机位** | 表：到被摄者距、α_cam、景别档、绑定镜头提示 |
| **站位点** | 表：相对各灯 / 机位 / 背景 / 窗的四类关系汇总；挂接的动作、镜头只读链接 |
| **人物元素** | 同站位汇总（无站位时的回退编辑入口） |

站位点工具栏：「站位」工具 → 选模特 → 点图画点；属性：坐标（显示系）、朝向、动作、镜头。模特档案（S3）只显示「n 个站位，查看」链到 S6，**不在档案里重算夹角**。

### 3.3 其它页（只读摘要，非编辑）

- **S5**：镜头详情可摘一句「L1 主光 45° 左」（消费关系结果，不另算一套）。  
- **S8**：站位缩略图；可不叠角度数字。  
- **EX**：见 §5，不新增夹角 UI。

### 3.4 不放的地方

- 不在 S0/S1、动作库、情绪板做夹角编辑。  
- 不把夹角做成用户手填字段（一律由几何推导；手填的是坐标/朝向/灯高/俯仰）。

## 4. 数据字段草案

### 4.1 已有、继续用

| 字段 | 位置 | 用途 |
|---|---|---|
| `x, y, rot` | 任意 layout 元素 | 平面位姿；`rot` = 水平朝向 |
| `kind` | 元素 | `light` / `camera` / `person` / `backdrop` / `window` … |
| `venue.w, d, h` | 场地 | 棚尺寸与显示系换算 |
| `setup.ex.subjectId` | 布光方案 | 默认被摄者（与 EX 对齐） |
| `faceFstop` / `faceLux` / `power` … | 灯 | **光比专用**，夹角模块只读几何，不写这些 |

### 4.2 建议新增（normalize 补默认；本方案只定名）

**灯元素（Q7 对齐，供关系 1 高度角）：**

```text
heightM: number | ""     // 灯高 m，默认 ""
pitchDeg: number         // 俯仰°，向下为负，默认 0
```

**站位点（新 kind 或独立数组，二选一见 §6）：**

```text
// 建议 A：layout.setups[].elements 增加 kind: "mark"
{
  id, kind: "mark",
  x, y,              // 存储系；UI 显示换算
  rot,               // 朝向 = 模特在此站位的正前
  personId,          // 绑定模特
  poseId: "",        // 可选，动作库
  shotIds: [],       // 可选，关联镜头
  label: ""
}
```

**人物可选：**

```text
faceHeightM: number | ""  // 默认空 → 用全局 1.4
```

**窗：无需新字段**；用法向规则从 `rot/w/h` 推导。若法向经常反，可加：

```text
inwardSign: 1 | -1      // 默认 1；翻转棚内法向
```

### 4.3 派生结果（不持久化，或仅缓存）

建议纯函数（未来进 `model.js`，本期不定实现）：

```text
relativeAngles(project, setupId, subjectRef) → {
  lights:  [{ lightId, dXY, dSlant, alphaDeg, side, keyName, elevDeg }],
  camera:  { cameraId, dXY, alphaDeg, side, viewLabel } | null,
  backdrop:{ backdropId, dMin, alphaDeg, side } | null,
  window:  { windowId, dMin, alphaDeg, side, incidenceDeg? } | null
}
```

- **不写入** JSON 工程文件（拖动时重算）。  
- 导出布置表时可把当时数值渲染进 PDF，仍非 schema 权威。

### 4.4 与现有 `distances()` 的关系

现有 `lightPerson` / `cameraPerson` / `personBackdrop` 只有距离。方案上由其扩展为「距离 + 夹角」，并**新增** `personWindow`；不要平行维护两套最近点逻辑。

## 5. 与 EX / 光比的边界

| | S6 相对夹角（本 Q3） | EX 光比（已有 T14，本期不加功能） |
|---|---|---|
| 数据源 | 同一份 `project.layout` | 同一份 |
| 关心量 | 方位角、距离、（灯）高度角、光位名 | 功率、距离平方反比、实测 EV、主辅比、是否在光束内 |
| 已有交叉 | EX 已用 `atan2` 算灯瞄准相对 `rot` 的 `offAxis`（光束内外） | **不是**「相对模特朝向的光位角」 |
| 边界 | 夹角模块**不**改 `lightRatios` 公式，**不**写 lux/f-stop | 光比**不**负责画量角器，不生成伦勃朗等光位名 |
| 可复用 | 同一 `subjectId`、同一平面距 `d` | 斜距若以后进估算，可调用同一 `d_slant`，属 EX 后续，不在本期夹角卡强绑 |
| 本期政策 | 确认稿：EX **只修 bug、不加功能** → 夹角 UI **只上 S6**（及 S5 只读摘句） | |

T24 文案里「相对机位轴线的角度」属于灯的附加标注，**不纳入本文件四种关系**；实现时可放在灯选中 HUD，但评审本 Q3 时可不阻塞。

## 6. 待确认问题（请 Hastin / Claude 勾选）

1. **左右符号**：α > 0 为模特**左侧**是否符合现场口语？还是要改成摄影常用「相机看模特时的左」？  
2. **背景夹角**：背景是否必须显示水平角，还是**只需距离**？  
3. **窗关系主显**：主显「窗相对模特朝向的方位角」还是「窗光入射角」？两者都显是否过载？  
4. **站位存储**：新 `kind: "mark"` 进 setup.elements，还是 `setup.marks[]` 独立数组？（建议 mark 进 elements，便于画布统一选中。）  
5. **多模特**：同一 setup 两人时，灯的关系页默认 `ex.subjectId` 还是「强制先选被摄者」？  
6. **光位名区间**：是否采用 0 / 30–60 伦勃朗 / 90 / 120–150 / 180 的分档，还是只要数字 + 左/右？  
7. **高度角**：关系 1 是否本期必做（依赖灯高字段与 T23），还是水平角先上、高度角跟 Q7 同一卡？  
8. **最近点 vs 中心点**：背景/窗的距离 MVP 用中心点是否可接受？  
9. **无站位时**：是否允许仅用 `person` 元素当顶点（建议允许，降低空状态）？  
10. **显示原点切换**：属性面板 X/Y 是否立即改为左下角显示（建议是），内部存储换算是否接受「只改显示层」？
